# 昭和美術印刷 コーポレートLP

Astro（静的出力 / TypeScript）+ 素のCSS で構築した1枚もののLP。
仕様は `design_handoff_showa_lp/README.md` に準拠。

## 開発

```sh
npm install
npm run dev      # http://localhost:4321
npm run build    # dist/ に静的出力
npm run preview
npm run check    # 型チェック
```

出力は完全な静的ファイルなので Vercel / Netlify / Cloudflare Pages のいずれでもホストできる。
クライアントJSはページ全体で約2.5KB（インライン）。

## 構成

```
src/
  styles/tokens/    デザインシステムのトークン（colors/typography/spacing/effects は verbatim）
  styles/tokens/lp.css  このLP固有のトークン（バンド高さ・duration・アイコンサイズ等）
  data/site.ts      ナビ・拠点・サービス・WORKSタイル・調整フラグ
  components/       SiteHeader / SectionRail / BackgroundVideo / WorkTile / ServiceIcon
                    ServiceModal / LocationRow / LinkButton / ContactActions / SpecTable
  sections/         TOP / ABOUT / WORKS / SERVICE / NETWORK / CONTACT
  scripts/          scroll-spy.ts（IntersectionObserver）/ background-video.ts
                    service-modal.ts（SERVICEポップアップ）
```

色・間隔・duration・easing はすべて `src/styles/tokens/` に集約。
セクション固有のスタイルは各 `.astro` の `<style>` にスコープされる。

## フォント

英字は **Adapter Mono PE Variable**（Adobe Fonts）、日本語は **Zen Kaku Gothic Antique**（Google Fonts）。

`--font-jp` などのスタックは**英字フォントを先頭に置いている**。Adapter Mono には
かな・漢字が無いため、「CTP出力」のような混在文字列は英字だけがAdapterで組まれ、
残りは自動的に Zen Kaku Gothic Antique に落ちる。1つの `font-family` で2書体になるので、
文字ごとにspanで囲む必要はない。**この2つの間に `sans-serif` などの総称ファミリーを
挟むと日本語がそちらで解決されてしまう**ので、順序は変えないこと。

### ウェイト

日本語は **500（Medium）**。カンプの実測から確定した値で、支給素材の「印」の
墨面積比 0.4118 に対し Zen Kaku Gothic Antique は 500 で 0.4232（300 は 0.1962、
400 は 0.3119）、「設備一覧」の横画の太さ比 0.1148 に対し 500 が 0.1081。
当初 300 で組んでいたが、これは別書体に見えるほど細く、カンプと明確に違っていた。

読み込むのは 500 だけ。日本語のWebフォントCSSは巨大で1ウェイトあたり約115KBあるため、
**別のウェイトを使い始めるときは `BaseLayout.astro` のリンクへ必ず足すこと**。
足さずに指定すると、ブラウザが最も近いウェイトから偽装して描画する。
Zen Kaku Gothic Antique に 200 は存在しない（`--fw-thin` は定義のみで未使用）。

英字ナビ（`.nav__link`）だけは `--fw-light`（300）のまま。Latin専用で日本語を含まず、
カンプの実測は Adapter Mono の 400〜500 相当（ステム比 0.14 に対し 400=0.1176、
500=0.1569）なので、確定させるならデザイナー確認のうえ調整する。

## 調整用フラグ

`src/data/site.ts` の `CONFIG` で一括変更できる。個別に上書きしたい場合は各セクションのpropsで渡す。

| フラグ | 既定 | 効果 |
|---|---|---|
| `useVideo` | `true` | `false` で全バンドの動画をフラットなグラデーションに差し替え |
| `showMap` | `true` | NETWORK の日本地図線画 |
| `serviceLabels` | `false` | SERVICE ピクトグラムのキャプション |
| `iconSize` | `300` | ピクトグラムの幅の上限。`--icon-size-base` を上書き |

バンド高さ・マーキー速度・ヘッダー高さなどは `src/styles/tokens/lp.css` の変数を触る。

NETWORK は左に地図、中央に縦の区切り線、右に拠点一覧。位置はすべて `--network-*`
（`lp.css`）にカンプ `拠点.jpg` の実測値を vw で入れてある。レールは WORKS と同じく
左右5%で、**セクション全体ではなく地図・住所ブロックの中心**に揃う（下のロゴは
レールが指す範囲の外）。ブロックの高さは内容で決まるので、`ResizeObserver` で
測って `--network-main-h` に渡している。

地図は輪郭・引き出し線・5つの拠点名が一体の1枚絵で、カンプ `拠点.jpg` から白線だけを
マット抜きして作る（`optimize-assets.sh` が素材ルート直下の `拠点.jpg` を見に行く）。

### ABOUT のステートメント

画像は**全幅（`width: 100%`、上限なし・左右パディングなし）**で置く。素材が他の
カンプと同じ 7681px の版（`アートボード 14@4x.png`、7681×3362）に描かれていて、
**版そのものがページ幅**だから。素材自身の余白によって文字は版幅の 57.61%
（インクは x 1608..6032）を占め、クライアントのモックアップでもウィンドウ幅の
57.57% なので、版をウィンドウ幅に合わせるだけで両者が一致する。

上限を付けないので**ウィンドウをどう伸縮させても画面内の占有率は変わらない**。
以前の `max-width: 1000px` は、ウィンドウが1000pxを超えた時点でこの比率が崩れていた。

`<picture>` にも明示的に `width: 100%` を与えている。flexアイテムのままだと
中身から幅を求めるが、この画像は遅延読み込みなので、読み込み前はラッパーが
0幅になり、画像の `width: 100%` が0に解決されて永久に出てこない。

左右のレールは、WORKS や NETWORK と同じく絶対配置にして画像の余白の上に重ねる。

### ヘッダーのロゴ

ロックアップは**漢字部分だけが白帯の中に入り、SHOWA ART PRINTING は帯の下へはみ出す**。
はみ出した英字の背後には何も敷かれないので、下にある映像やページがそのまま透ける。

- 漢字の下端＝白帯の下端。`--logo-kanji-frac`（`lp.css`）がロックアップ全高に占める
  漢字部分の割合で、`lockup.png`（456×261、アルファを白に合成して実測）の
  漢字インクが 9〜192行、英字が 242〜260行なので境界は 193 行目 → `193/261 = 0.7395`
- `.header__logo` の高さをこの割合分にして、画像自体は原寸のままはみ出させる。
  クリップは効かない（`.header-bar` は `position: fixed` なので包含ブロックは
  ビューポート）
- `--header-h` も同じ割合で算出し、**下パディングを含めない**。ヘッダー側も
  `padding-bottom: 0`。帯の高さは 117px → 80px に縮んだ
- 下パディングが無い分ナビが下寄りになるので、`.nav` に `margin-bottom:
  var(--header-pad-top)` を入れて帯の中心線に戻している（中央揃えの要素は
  下マージンの半分だけ上がる）
- **モバイル（768px以下）は `--logo-kanji-frac: 1`**。ナビがロゴの真下に来るため、
  英字がはみ出すとナビに被る。全ページ共通で、`/facility` も含め例外は無い

#### はみ出した英字の色（`logo-contrast.ts`）

英字は背景の上に直接乗るので、暗い背景だと黒いままでは沈む。ヘッダーは
`position: fixed` で、スクロールにつれても動画の再生につれても背後が変わるため、
**ページごとに色を決め打ちせず、実際に背後にあるものを読んで**白黒を切り替える。

- ロックアップは1つのファイルを2回描いている。`clip-path` で
  **漢字側（白帯の中）と英字側（はみ出す分）を別々の要素**にしてあるので、
  英字だけを白にできる
- 白にするのは `filter: invert(1)`。元の絵が「黒＋透明」なので、反転すると
  白になり透明部分はそのまま残る
- 背後の判定は、英字の矩形に 6×2 の点を打ち、各点で `elementsFromPoint` を
  上から辿って**最初に実際に色を塗っているもの**を探す。動画と画像は canvas に
  縮小描画して該当ピクセルを読む（`object-fit: cover/contain/fill` を補正）。
  アルファが薄いピクセルは「そこは透けている」として奥へ辿る
  （NETWORKの地図は白線＋透明なので、額面で受け取ると地図を読んでしまう）
- 動画が未デコードのときは `poster` を代わりに読む。`prefers-reduced-motion`
  では動画がそもそも再生されず、poster が表示の全てになるため
- しきい値は相対輝度 **0.179**。白とのコントラスト比 `1.05/(L+0.05)` と黒との
  `(L+0.05)/0.05` が交差する点で、これを下回ると白のほうが読みやすい
- CSSの `mix-blend-mode: difference` で済ませようとしたが**使えない**。
  彩度のある映像に対しては補色が返るので、オレンジの上で英字が青くなる
- 再評価はスクロール・リサイズ・`visibilitychange` と、背後にメディアがある間
  だけ回る250msのポーリング。バックグラウンドのタブでは `requestAnimationFrame`
  が止まるので、`visibilitychange` が無いと初回評価が走らないまま黒で固まる

フッターはヘッダーと対になる白帯。**帯の高さそのもの**を `--header-h`（ヘッダーの
スペーサーが使うのと同じ値）に揃えてあるので、両者は幅によらず同じ厚みになる。
上のロゴ変更で `--header-h` が縮んだぶんフッターも一緒に縮む（実測 80.3px で一致、
ボタン43pxに対し上下20px前後の余白）。
左右のガターと上下パディングも同じトークンを共有する。ヘッダー側はモバイル指定も
含めてこのトークン参照なので、片方だけずれることはない。

この浅い帯に収まるよう、CTAは本文より一段小さい `--footer-cta-size` で組む。
モバイルは2段に積むが、その2段が `--header-h` に収まる間隔にしてあるため、
そこでも帯の高さが基準として効く。

WORKS のタイルは普段「蓋」（`WORK_TILES` の `lid`）を被っていて、マウスを乗せると
下の実績写真がクロスフェードで現れる。蓋は各写真の背景色に合わせた流し素材で、
対応はCIE Labの色距離で確認済み（4枚とも最も近いのがファイル名どおりの組み合わせ）。
**蓋も下の実績写真もクライアント指定により無圧縮・原寸のまま**（どちらも3274×2304前後、
蓋が各160〜200KB、写真が各390〜650KB）で、`optimize-assets.sh` は再エンコードせず
コピーするだけ。WebP版は置いていない（理由は「アセット」の節）。

タッチ端末にはホバーが無いので `@media (hover: hover)` で囲ってある。ホバーできない
環境では蓋を出さず、最初から実績写真を表示する。

WORKS はレールを画像の上に白文字で重ねる（他セクションのように脇の余白へ置かない）。
マーキーは画面幅いっぱいに流れ、ラベルはその上に絶対配置される。左右の内側位置は
`--works-rail-inset`（カンプ実測で 5.00%）。ラベルは `pointer-events: none` なので、
カーソルを乗せたときのマーキー一時停止を妨げない。

`iconSize` は上限値で、実際の描画サイズは SERVICE 側で算出する。3列並びの1行目が
レールの内側に収まらない幅ではアイコンが縮み、横スクロールは発生しない
（1366px以上で300px、1280pxで291px、900pxで164px）。768px以下では
`--icon-mobile-scale`（0.72）を掛けた値になる（300px → 216px）。

## SERVICE のポップアップ

各ピクトグラムはボタンで、クリックすると対応する `<dialog>` が開く。
ネイティブの `<dialog>` なので Esc・フォーカストラップ・背面の inert 化・
フォーカスの復帰はブラウザ任せ。`service-modal.ts` が足すのは開くクリック、
スクロールロック、スクリムのクリックで閉じる処理、写真の先読みだけ。

- ヘッダーの下端から始まり `::backdrop` は透明。ヘッダーだけが鮮明に残る
- スクリムは `--popup-scrim`（白 94%）。背面のピクトグラムが約6%で透ける
  ＝カンプの「うっすら見える」状態。セクション側のレールは重複するので開いている間だけ隠す
- スクロールロックは `open` 属性を MutationObserver で見て同期する。`close`
  イベント頼みだと取りこぼした時にページが二度とスクロールできなくなる
- 版面の比率は `--popup-*` トークン（`lp.css`）に集約。カンプ（7681px幅の板）の
  実測値を 7681 で割った vw なので、どの横幅でも構図が保たれる
- 文字サイズはカンプの墨（インク）実測 ÷ 書体の字面率（Zen Kaku Gothic Antique
  の「印」は 0.905em）で逆算。字間・行間もカンプの字送り・行送りの実測値で、
  共通トークンの `--ls-*` / `--lh-*` は使わない（カンプがそれに従っていないため）
- 見出しの字間は共通 0.47em、オンデマンドだけカンプ通り 0.16em（`titleTrack`）
- 設備一覧と×は見出し1列目に連動する1ユニット（×は1列目の中心、罫線右端は
  ×中心から372px相当）。2列見出しのパネルでもカンプ通りの位置になる

文言は `SERVICE_ROWS` の `titleLines` / `bodyLines`。どちらも縦組みの列で、
先頭が一番右の列になる（例：`['オフリン', '印刷']`）。本文の改行位置は
カンプの列そのままに固定してある。

## アセット

**`public/assets/` は支給素材を一切再圧縮していない。** クライアント指定により、
リサイズも再エンコードも行わず、バイト単位のコピー・ストリームコピー・切り抜き・
可逆エンコードのいずれかだけを通す。再生成は素材の置き場所を渡して実行する
（省略時は `~/Downloads`）。

```sh
./scripts/optimize-assets.sh [/path/to/materials-root]
```

以下の構成を前提にしている。無いものはスキップされる。

| 素材 | 置き場所 |
|---|---|
| TOPループ動画 A/B/C | ルート直下 `昭和LPデザインTOP動画{A,B,C}.mp4` |
| NETWORK動画・TOPバー | `　昭和美術印刷LP素材_まとめ/　昭和美術印刷LP素材_TOP/` |
| ステートメント | `　昭和美術印刷LP素材_まとめ/　昭和美術印刷LP素材_ステートメント/` |
| 印刷アイコン5種 | `　昭和美術印刷LP素材_まとめ/　昭和美術印刷LP素材_印刷アイコン/` |
| POPUP合成PNG・閉じるボタン | `　昭和美術印刷LP素材_印刷アイコンからのPOPUP表示/` |
| WORKS 実績写真 | `　昭和美術印刷LP＿ワークス＿JPG/` |
| WORKS 蓋（流し素材）・`拠点.jpg` | ルート直下 |

必要なツール: `ffmpeg`, `cwebp`（`brew install ffmpeg webp`）, `python3` + Pillow。

扱いは素材の性質で決まる。

- **動画** — 映像ストリームをそのままコピー（`-c:v copy`）。1920×1080・元ビットレート
  のままで、**映像エレメンタリストリームが支給マスターとバイト単位で一致**する
  ことを確認済み（`-f h264` で抜き出してSHA比較）。捨てるのは再生しないAAC
  トラックのみ。`+faststart` 付き。WebMは**廃止**した。あれはエンコード済み素材の
  二度目のエンコードで、しかもブラウザがmp4より優先するため、劣化した方が常に
  表示されていた
- **動画のポスター画像** — 1フレーム目を**可逆**WebPで書き出す（`-poster.webp`）。
  これは支給物ではなくこちらで作る画像なので、劣化があればこちらが入れた劣化に
  なる。かつ `prefers-reduced-motion: reduce` では動画が再生されずポスターが
  表示の全てになるため使い捨てではない。PNGではなく可逆WebPなのは同じピクセルが
  2/3のサイズに収まるから（top-a で 1215KB → 813KB）。元フレームとピクセル単位で
  一致することを確認済み
- **JPEGで支給された写真**（WORKS 実績写真・蓋）— 支給ファイルをそのままコピー。
  3274×2304。WebP版は**置かない**：JPEGの再エンコードは二世代目の劣化になり、
  可逆WebPにすると元のJPEGより大きくなるだけなので、`<picture>` から
  `<source>` を外して1ファイルにした
- **PNGで支給された平面素材**（ステートメント・アイコン・閉じるボタン）— 原寸を
  そのままコピーし、加えて**可逆**WebPを置く。両者はピクセル単位で同一
- **SERVICEポップアップの写真** — 支給された合成PNG（写真＋文字が焼き込まれた1枚絵）
  から写真部分だけを原寸で切り抜く。5枚とも同じ 3432x1974 の位置にあるので矩形は共通。
  中身は写真なのでPNGだと5枚で41MB、可逆WebPなら26MBになる。ピクセルが完全に
  一致することを確認した上で**可逆WebPのみ**を置いている
- **NETWORK地図** — カンプ `拠点.jpg` から白線だけをマット抜きしたもの。
  1787×2306の原寸（以前は1400pxに縮小していた）
- 画面外の動画は IntersectionObserver で一時停止し、未表示のものは読み込まない
- `prefers-reduced-motion: reduce` で動画と WORKS マーキーの両方を停止

### TOPのループ動画（ランダム再生）

TOPのヒーローは `top-a` / `top-b` / `top-c` の3本から**読み込みごとに1本を抽選**する。
本数や採用クリップを変えるのは `TOP_VIDEOS`（`src/data/site.ts`）の1行だけでよい。
各basenameに `.mp4` と `-poster.webp` が揃っていれば他は触らなくていい。

抽選はビルド時ではなく**ブラウザ側**で行う（`dealVariant()` in
`src/scripts/background-video.ts`）。静的ビルドなので、レンダリング時に引くと
全員が同じ1本を見ることになるため。

- `BackgroundVideo` は `name` に文字列も配列も取る。配列のときだけ
  `data-variants` を出し、`poster` と `data-mp4` は空にしておく
- **複数のときマークアップに `poster` を置かないのは意図的。** どれが正解かは
  抽選まで決まらないので、静的に置くと一度表示してから差し替わってちらつく。
  その一瞬はバンドの `--gradient-fire` が受け持つ
- 抽選は `initBackgroundVideo()` の冒頭、IntersectionObserver より前に走らせる。
  ヒーローは最初から画面内にあり、かつ `prefers-reduced-motion: reduce` では
  動画が再生されず **poster が表示の全てになる**ため、可視判定を待てない
- JSが無い環境向けに `<noscript>` で `top-a` のポスターを出す。JSが無いと
  そもそも `<source>` が付かず動画は再生されないので、ここが唯一の絵になる
- ダウンロードされるのは当たった1本だけ（4.3〜5.8MB）。固定19MBだった以前より軽い

### サイズ

無圧縮化で `public/assets/` は 11MB → 59MB になった。内訳は SERVICE ポップアップ
26MB、動画 24MB、設備一覧 2.9MB、WORKS 2.6MB、残り 1MB 弱。

- TOP動画は3本で計14MB（A 5.8MB / B 4.3MB / C 4.6MB）だが、1回の閲覧で落ちるのは
  当たった1本だけ。`preload="none"` なので `poster`（0.4〜0.8MB）が先に出る
- ポップアップ写真は1枚2.5〜7.7MB。ダイアログを開くまで読み込まないうえ、
  アイコンのホバーで先読みを始めるので実際に待たされる場面は少ないが、
  製本折加工の7.7MBは体感に出うる
- ブランドロックアップ（`brand/lockup*.png`、456px/840px）だけは元データが
  どの素材フォルダにも無く、旧ハンドオフzipのラスターのままになっている。
  ベクターか原寸の書き出しがあれば差し替えたい

## 未確定・要クライアント確認

- **実績写真** — WORKS は現在4タイル（おしごと本／スキージャム／ヨーロッパ軒／田村屋）で、すべてクライアント支給の原本（3274×2304）をそのまま使っている。増やすときは `WORK_TILES`（`src/data/site.ts`）に写真と蓋のペアを足す。
- **TOP動画BとNETWORK動画が同一** — `昭和LPデザインTOP動画B.mp4` は NETWORK バンドで流している `動画素材B.mp4` とフレーム単位で完全に同一だった。支給どおり両方に置いてあるが、抽選でBが当たるとTOPとNETWORKで同じ映像が流れることになる。意図どおりか、TOPのBを別クリップに差し替えるか要確認。
- **旧 動画素材A / 動画素材C** — どちらも使用をやめた。Aは固定ヒーローで新しい3本に置き換わり、Cは置き場所が無いまま（WORKSの動画タイルが廃止されたため）。
- **RECRUIT / 採用情報・お問い合わせのリンク先** — 専用セクションがないため現在はすべて `#contact`。
- **設備一覧ページ（`/facility`）** — カンプ `仮＿設備一覧ページ.jpg` から起こした。
  ファイル名が「仮」なので内容・レイアウトとも要確認。特に次の3点：
  - カンプは自由配置の1枚絵（7681×18744）。本文が読める大きさを保つため、
    構造（部門ブロック／仕様リスト／機械写真）は忠実に、配置は縦に流れる組みに直した。
    ピクセル単位の重なりまでは再現していない。
  - 見出しが**明朝**で、サイト唯一のゴシック以外。Shippori Mincho を当てているが、
    カンプの実際の書体は不明なので指定があれば差し替える（`--fac-font-display`）。
  - カンプ内で表記ゆれ：仕様リストは「自動平盤打**技**機」、写真キャプションは
    「自動平盤打**抜**機」。打抜機が正なので両方そちらに揃えた。
  - ナビは指示どおり `FACILITIES`。ただしPOPUPカンプのナビ表記は `FACILITY`（単数）。
  機械写真はカンプから切り出したもの。地が純黒なのでマット抜き不要で、
  矩形のまま切り出せばページの黒に馴染む。
- **ポップアップの文言（画像 → テキスト化）** — 支給素材は写真に文字が焼き込まれた1枚絵だが、
  そのまま貼るとスマホで本文が数px相当になり、選択・読み上げ・翻訳もできない。
  写真だけを切り出し、見出しと本文は縦組みのライブテキストとしてカンプの
  寸法・字間・改行位置の通りに組んである（`bodyLines`）。「ＣＴＰ」は
  カンプに合わせて全角（半角だと縦組みの正立で送りが崩れる）。
- **「オフリン印刷」の表記** — 支給されたアイコン一覧の名称に合わせて `オフセット印刷` から
  変更した（オフ輪＝輪転機のことで、枚葉印刷と別物のため）。正式表記を要確認。
- **MAPリンク** — `拠点.jpg` のカンプでは住所の後ろの MAP リンクが無くなっているため、
  表示をやめた（それ以前の全体像カンプには有った）。`mapHref()`（`data/site.ts`）は

- **Adobe Fonts のドメイン登録** — Adapter Mono PE Variable（キット `pxu0snp`）はドメイン制限つき。
  現ステージング（`chikuwa-taso.github.io`）では読み込みを実機確認済みだが、**本番ドメインに移す際は
  Adobe の Web プロジェクトにそのドメインを追加すること**。追加しないと警告なくシステム等幅にフォールバックする。
